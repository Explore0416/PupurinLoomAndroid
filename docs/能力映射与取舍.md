# 能力映射与取舍

本文档对照桌面版 `window.pupurin`（preload / main 进程）的完整 API 面，说明 Android 版的实现方式与不可避免的取舍。

## 1. 完整 API 能力映射

| 桌面版 API | Android 实现 | 说明 |
| --- | --- | --- |
| `getBackendPort` | 返回 `null` | 无独立 Python 后端 |
| `getBackendStatus` | 返回 `{ running:false, port:null, pid:null }` | 解析已本地化，不再需要后端进程 |

## 2. 核心取舍

1. **不再有 Python 后端进程**：Ren'Py 脚本解析分别本地化为渲染层 TS（`parser.ts`）与 Kotlin（`ProjectStore`），整体更轻、完全离线可用。为此 `getBackendStatus` 恒返回「未运行」。

2. **项目沙盒化**：项目统一存 `filesDir/projects`，无法直接访问任意磁盘目录。外部资源通过 SAF 选择器导入。`pickDirectory` / `revealPath` / `showProjectInFinder` 因此退化为 no-op。

3. **设备端「运行/打包」的边界与已实现路径**：真正的「打包 APK」仍需要桌面 Ren'Py SDK + JDK（RAPT 是桌面工具链），设备端无法离线完成。但在设备端「运行已导出的游戏」现已实现：SAF 选择已导出的 Ren'Py 游戏 APK → 复制到缓存 → 弹出系统安装器（API 26+ 自动引导「安装未知应用」授权）→ 安装完成后自动启动。该路径无需在 App 内嵌引擎，因为导出的 APK 自身携带引擎。若要进一步做到「内嵌引擎、以游戏目录直接启动」（不依赖 APK），需先运行 `tools/extract-renpy-runtime.sh <游戏apk>` 把引擎原生库（`lib/<abi>/*.so`）+ Python 运行时提取进 `app/src/main/jniLibs/` 与 `assets/renpy/`，再按实际引擎入口实现/校准 `PlayerActivity` 的本地引导（`hasRenpyEngine()` 会据此返回 true）。引擎二进制是真实产物、无法凭空生成，故这是一个标准化的提取/接入流程，而非代码可绕过的限制。

4. **插件禁止命令执行**：`pluginExec` 出于安全考虑不实现，返回说明。插件其余能力（面板、命令、受限文件读写、HTTP、商城）完整保留。

5. **无原生菜单栏**：桌面版顶部菜单在 Android 无对应物，相关 IPC 为 no-op，不影响核心编辑流程。

6. **布局适配的边界**：原版是桌面 IDE 布局。Android 版依赖渲染层的响应式能力与 `<meta viewport>`；平板横屏体验最佳，手机竖屏可用（受限但功能完整）。如需针对窄屏深度重排，需对前端做额外响应式改造（属于前端次优事项）。

## 3. 自适应与小窗实现细节

- **横竖屏 / 多尺寸**：`screenOrientation="unspecified"`，`configChanges` 声明 `orientation|screenSize|screenLayout|smallestScreenSize|density|fontScale|locale|uiMode|keyboardHidden|keyboard|layoutDirection`，旋转/缩放不重建 Activity。
- **小米「无极缩放」自由窗口 / 分屏**：`resizeableActivity="true"`，未设置 `maxAspectRatio`，可任意比例缩放。
- **「小窗」画中画（PiP）**：`supportsPictureInPicture="true"`，`onUserLeaveHint` 按 Home 键进入悬浮小窗（API 26+）；当正在拉起 SAF 选择器或外部浏览器时自动抑制，避免误入 PiP。
